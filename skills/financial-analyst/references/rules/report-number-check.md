관련 스펙: `specs/002-report-number-check/` (FR-013)  
최상위 헌법 원칙: II(출처 추적), III(조용한 오류 금지), IV(단일 원본), VI(Clean-Slate)

## 1. 보고서 구간

| 구간 | 판별 | 점검 |

## 2. 수량이 아닌 표기 (제외)

숫자를 읽기 전에 아래 표기를 지운다(위치는 유지). 범주별 개수를 보고한다. 표의 순서대로 적용하되, `numbering`은 두 번 나눠 적용한다: 줄 머리 번호·섹션 참조·`N번`은 `citation` 바로 다음(날짜보다 먼저), 단위 없는 한 자리 정수는 숫자를 읽은 뒤 마지막.

| 키 | 범주 | 예 | 판별 |
|---|---|---|---|
| `diagram_style` | 다이어그램 서식 | `classDef x fill:#f9f9f9,stroke-width:2px`, `#512da8` | Mermaid 블록의 `style`·`classDef`·`linkStyle`·`class` 줄 전체, 16진 색상 |
| `citation` | 인용·출처 표기 | `[7]`, `[7], [8]`, `KI-001`, URL, `` `파일_20261014.json` `` | 인용 번호, 사건 번호, URL, 인라인 코드 |
| `date` | 날짜·시각 | `2026-10-28`, `2026-10`, `10-14`, `10월 27~28일`, `10월`, `15:00` | 날짜·시각 패턴 |
| `ticker_code` | 종목·지수 코드 | `005930`, `005930.KS`, `^KS11` | 6자리 숫자(+`.KS`/`.KQ`), `^`로 시작하는 지수 코드 |
| `period_label` | 분기·회계 표기 | `3Q26`, `FY4Q26`, `1H26`, `FY1`, `3분기` | 영문 기간 표기, `N분기` |
| `product_spec` | 제품·공정·규격 | `HBM4`, `LPDDR5X`, `MI350`, `16-Hi`, `4나노`, `3nm`, `12단`, `2048-bit`, `1c`, `6세대` | 영문자와 붙은 숫자, 규격 단위(아래 표) |
| `duration` | 기간 | `30일`, `5거래일`, `20일간`, `1~5거래일간`, `52주 최고가`, `12M`, `3개월` | 정수 + 기간 단위, `52주` 뒤에 최고·최저·고점·저점·범위 |
| `year` | 연도 | `2027년`, `2022→2023`, `2026` | 단위·통화 없는 1900~2099 정수 |
| `numbering` | 번호·개수 | `6.1`(제목), `1)`, `Section 4 › 1-1`, `5번`, 단위 없는 한 자리 정수 | 줄 머리 번호, 섹션 참조, `N번`, 단위·통화·부호·소수점 없는 0~9 |

규격 단위(숫자 뒤에 붙으면 `product_spec`):

| 키 | 뜻 |
|---|---|
| `nm` | 공정 |
| `나노` | 공정 |
| `단` | 적층 |
| `Hi` | 적층(`16-Hi`) |
| `bit` | 버스 폭 |
| `세대` | 세대 |

용량 단위(`GB`, `TB`)가 붙은 숫자는 수량으로 대조한다(spec Edge Cases).

## 3. 숫자 읽기

- 형태: `부호? 통화? 숫자 단위?`. 부호는 `+`, `-`, `−`. 통화 기호 `₩`, `$`와 통화 표기 `TWD`, `USD`, `KRW`, `원`은 값 비교에서 무시한다.
- 숫자는 쉼표 천 단위(`1,076.75`) 또는 일반 소수. 소수 자릿수 d를 기록한다.
- **한글 금액**: `3조 9,334억 원` → 하나(값 3.9334, 단위 `조`, 소수 4자리). 부호는 앞에 붙은 것을 쓴다.
- **범위**: `26.5%~31.2%` → 둘. 앞 숫자에 단위가 없고 `~` 바로 뒤 숫자에 단위가 있으면 단위·통화를 물려받는다(`50~60%`).
- **말로 쓴 방향**: `34.3% 하락` → 부호 없는 표기로 본다.

## 4. 스크립트 값 일치

### 4-1. 허용 오차

표기의 소수 자릿수가 d이면 |후보 − 표기| ≤ 0.5×10⁻ᵈ (부동소수 여유 10⁻⁹).

### 4-2. 단위 배율

스냅샷 값 v에 배율을 곱한 후보 v×s를 표기 값과 비교한다. 단위마다 아래 배율을 모두 시도한다.

| 키 | 배율 | 뜻 |
|---|---|---|
| `%` | 100, 1 | 소수 비율, 퍼센트 값 |
| `%p` | 100, 1 | 비율 차이 |
| `조` | 1e-12, 1e-4 | 원 단위 값, 억 원 단위 값 |
| `억` | 1e-8, 1 | 원 단위 값, 억 원 단위 값 |
| `만` | 1e-4 | |
| `T` | 1e-12 | |
| `B` | 1e-9 | |
| `M` | 1e-6 | |
| `K` | 1e-3 | |
| `배` | 1 | |
| `x` | 1 | |
| `건` | 1 | |
| `주` | 1 | |
| `GB` | 1 | |
| `TB` | 1 | |
| `bp` | 1, 1e4 | |
| (없음) | 1 | 통화 기호만 있거나 단위 없음 |

### 4-3. 부호

표기에 `+`·`-`가 있으면 후보와 부호가 같아야 한다(0은 둘 다 허용). 부호가 없으면 절댓값으로 비교한다.

### 4-4. 정보량 낮은 숫자

소수점 없는 두 자리 이하 정수(|값| < 100)는 우연히 맞기 쉽다.

- 같은 줄이나 가장 가까운 상위 제목에서 종목(스냅샷 `meta.args.tickers`)이 특정되면 그 종목 경로(`{티커}.`)와 `rules.`에서만 찾는다.
- 종목을 특정할 수 없으면 모든 경로에서 찾되, 일치하면 `weak`(약한 일치)로 표시해 검토 목록에 따로 보여 준다.

### 4-5. 여러 경로와 일치

문맥 종목의 경로를 우선하고, 일치한 경로 수를 함께 적는다.

## 5. 분류

순서: 제외 → 스냅샷 일치(`script`) → 인용 범위 안 인용(`cited`) → 나머지(`unsupported`).

**인용 범위**: 같은 문장(`다.`·`. `·`<br>`·줄바꿈으로 나눔, 목록 항목도 문장 단위) 또는 같은 표 행(`|`로 시작하는 줄 하나). 범위 안의 `[n]`이 그 범위 숫자 전체의 인용이다.

**직접 계산 금지**: 스냅샷 값으로 AI가 계산한 숫자(합계·차이·비율 등, 스크립트가 내지 않는 값)는 `unsupported`다. 같은 값의 단위·표기만 바꾼 것은 4-2 규칙으로 일치한다.

## 6. 참고문헌 형식

- 항목: 참고문헌 구간의 `[n] …` 줄. `[n] 제목 — 발행일 — URL`과 `[n] [제목](URL) — 발행일`을 모두 읽는다.
- 필수: 제목, 발행일(`YYYY-MM-DD`), URL.
- **홈페이지 주소**: 경로가 비었거나 `/`, `/index.html`, `/index.htm`, `/main`, `/home`뿐이고 쿼리가 없는 URL. 출처로 인정하지 않는다.
- 본문의 인용 번호가 참고문헌에 없으면 `missing_citation_target`(오류), 참고문헌이 본문에서 쓰이지 않으면 `unused_reference`(경고).

## 7. 기사 대조 (`--fetch-sources`, 로컬 전용)

| 키 | 뜻 |
|---|---|
| `found` | 그 번호로 인용된 숫자가 모두 문서에 있음 |
| `not_found` | 문서에 없는 숫자가 있음 |
| `unverifiable` | 접속 실패, 홈페이지 주소, 본문 글자 500자 미만(유료·차단 추정) — 통과 아님 |

제한 시간 10초, 재시도 없음. 문서 숫자는 3장의 규칙으로 읽고, 같은 단위끼리 4-1 허용 오차로 비교한다(`조`↔`억`은 서로 환산).

## 8. 결과와 종료 코드

| 키 | 뜻 |
|---|---|
| `0` | 기록되지 않은 오류 없음 |
| `1` | 기록되지 않은 오류 있음 |
| `2` | 실행 불가(보고서 없음·읽기 실패·인자 오류) |

- 문제 ID: 숫자 문제는 `{섹션 제목 SHA-1 앞 4자}-{원문 표기}-{같은 섹션 안 같은 표기의 순번}`, 그 밖에는 `{종류}-{대상}`(예: `reference_format-7`).
- '숫자 점검 결과' 섹션: 참고문헌 목록 뒤, 면책 문구 앞에 `## 9. 숫자 점검 결과 (스크립트 자동 점검)`으로 넣는다. 다시 점검할 때 머리 줄의 개수가 현재 결과와 같고, 남은 문제의 ID가 표에 있고 사유가 `[AI_TODO]`가 아니면 그 문제는 '기록됨'이다.
- 짝 스냅샷이 없으면 `no_snapshot`, Section 4 기준본이 없으면 `no_baseline` 오류를 낸다(조용히 통과하지 않음).
