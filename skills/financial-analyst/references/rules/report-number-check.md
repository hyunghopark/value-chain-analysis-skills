코드: `scripts/check_report_numbers.py`  
관련 스펙: `specs/002-report-number-check/` (FR-013)  
최상위 헌법 원칙: II(출처 추적), III(조용한 오류 금지), IV(단일 원본), VI(Clean-Slate)

## 2. 수량이 아닌 표기 (제외)

숫자를 읽기 전에 아래 표기를 지운다(위치는 유지). 범주별 개수를 보고한다. 표의 순서대로 적용하되, `numbering`은 두 번 나눠 적용한다: 줄 머리 번호·섹션 참조·`N번`은 `citation` 바로 다음(날짜보다 먼저), 단위 없는 한 자리 정수는 숫자를 읽은 뒤 마지막.

| 키 | 범주 | 예 | 판별 |
|---|---|---|---|
| `diagram_style` | 다이어그램 서식 | `classDef x fill:#f9f9f9,stroke-width:2px`, `#512da8` | Mermaid 블록의 `style`·`classDef`·`linkStyle`·`class` 줄 전체, 16진 색상 |
| `citation` | 인용·출처 표기 | `[7]`, `[7], [8]`, `KI-001`, URL, `` `파일_20261014.json` `` | 인용 번호, 사건 번호, URL, 인라인 코드 |
| `date` | 날짜·시각 | `2026-10-28`, `2026-10`, `10-14`, `10월 27~28일`, `10월`, `15:00` | 날짜·시각 패턴 |
| `ticker_code` | 종목·지수 코드 | `005930`, `005930.KS`, `^KS11`, `S&P 500` | 6자리 숫자(+`.KS`/`.KQ`), `^`로 시작하는 지수 코드, 숫자가 들어간 지수 이름(S&P 500·KOSPI 200·NASDAQ 100) |
| `period_label` | 분기·회계 표기 | `3Q26`, `FY4Q26`, `1H26`, `FY1`, `3분기` | 영문 기간 표기, `N분기` |
| `product_spec` | 제품·공정·규격 | `HBM4`, `LPDDR5X`, `MI350`, `16-Hi`, `4나노`, `3nm`, `12단`, `2048-bit`, `1c`, `6세대`, `-2σ` | 영문자와 붙은 숫자, 규격 단위(아래 표) |
| `duration` | 기간 | `30일`, `5거래일`, `20일간`, `1~5거래일간`, `52주 최고가`, `12M`, `3개월`, `20분` | 정수 + 기간 단위, `52주` 뒤에 최고·최저·고점·저점·범위 |
| `year` | 연도 | `2027년`, `2022→2023`, `2026` | 단위·통화 없는 1900~2099 정수 |
| `numbering` | 번호·개수 | `6.1`(제목), `1)`, `Section 4 › 1-1`, `5번`, 단위 없는 한 자리 정수 | 줄 머리 번호, 섹션 참조, `N번`, 단위·통화·부호·소수점 없는 0~9 |

| 키 | 뜻 |
|---|---|
| `nm` | 공정 |
| `나노` | 공정 |
| `단` | 적층 |
| `Hi` | 적층(`16-Hi`) |
| `bit` | 버스 폭 |
| `세대` | 세대 |

용량 단위(`GB`, `TB`)가 붙은 숫자는 수량으로 대조한다(spec Edge Cases).

## 3. 숫자 읽기

- 형태: `부호? 통화? 숫자 단위?`. 부호는 `+`, `-`, `−`. 통화 기호 `₩`, `$`와 통화 표기 `TWD`, `USD`, `KRW`, `원`은 값 비교에서 무시한다.
- 숫자는 쉼표 천 단위(`1,076.75`) 또는 일반 소수. 소수 자릿수 d를 기록한다.
- **한글 금액**: `3조 9,334억 원` → 하나(값 3.9334, 단위 `조`, 소수 4자리). 부호는 앞에 붙은 것을 쓴다.
- **범위**: `26.5%~31.2%` → 둘. 앞 숫자에 단위가 없고 `~` 바로 뒤 숫자에 단위가 있으면 단위·통화를 물려받는다(`50~60%`).
- **말로 쓴 방향**: `34.3% 하락` → 부호 없는 표기로 본다.

## 4. 스크립트 값 일치

### 4-1. 허용 오차

표기의 소수 자릿수가 d이면 |후보 − 표기| ≤ 0.5×10⁻ᵈ (부동소수 여유 10⁻⁹).

### 4-2. 경로 종류

스냅샷 경로를 끝부분 모양으로 종류를 나눈다. 위에서부터 처음 맞는 종류를 쓴다(정규식, 경로 전체에 `search`).

| 키 | 경로 패턴 | 예 |
|---|---|---|
| `volume` | `\.volume(\.\|$)` | 거래량 이력 |
| `flow_amount` | `\.flows\.[^.]+\.\w+_amt$` | 수급 추정 금액(억 원), 5일 누적 |
| `shares` | `_shares$` | 순매수 수량 |
| `count` | `(up\|down)_30d$\|_count$` | 추정치 상향·하향 건수, 애널리스트 수 |
| `percent` | `\.(debt_to_equity\|deviation_lower\|deviation_upper\|dividend_yield)$\|_pct$` | 퍼센트 값으로 저장된 지표 |
| `fraction` | `\.(return_\w+\|drawdown_52w\|\w*margin\|roe\|roa\|\w*growth\|payout_ratio\|held_percent_\w+\|short_percent_\w+\|foreign_hold_ratio\|percentile\|position\|upside\w*\|opm_ttm\|change_30d\|surprise\|max_income_drop\|\w*vs_avg\|weight_\w+\|eps_range_width)$\|\.cycle\.opm\.` | 소수 비율(0.52 = 52%) |
| `multiple` | `\.(beta\|current_ratio\|dupont_leverage\|ev_to_\w+\|\w*_pe\|peg_ratio\|price_to_\w+\|multiple_[ab]\|pe)$\|\.pb_band\.(pb\.\|high$\|low$\|median$\|current_pb$)` | PER, P/B, EV/EBITDA, 베타, 재무레버리지 |
| `money` | `\.(market_cap\w*)$\|\.audit\.` | 시가총액, 일회성 손익 금액 |
| `price` | `(close\|price\|eps\|_high\|_low\|bps\|sma_20\|bollinger_\w+\|book_value\|dividend_rate)(_[ab])?(\.\|$)\|\.history\.\|\.target` | 주가, EPS, 목표가, 시나리오 기대값 |
| `other` | `.` | RSI 등 나머지 |

### 4-3. 단위와 경로 종류

가격 이력(`series`)은 종목·지수마다 마지막 날짜 값만 대조한다(본문은 현재 가격을 인용하고, Section 4가 보여 주는 날짜별 값은 `values`에 따로 있다). 표기 단위마다 대조할 경로 종류와 배율이 정해져 있다. 스냅샷 값 v에 배율 s를 곱한 v×s를 표기 값과 비교한다. 표의 순서가 우선순위다(여러 경로가 맞으면 앞 종류를 고른다).

| 키 | 대조할 경로 종류(배율) |
|---|---|
| `%` | `fraction` ×100, `percent` ×1 |
| `%p` | `fraction` ×100, `percent` ×1 |
| `조` | `money` ×1e-12, `flow_amount` ×1e-4 |
| `억` | `money` ×1e-8, `flow_amount` ×1 |
| `만` | `money` ×1e-4, `shares` ×1e-4, `volume` ×1e-4 |
| `T` | `money` ×1e-12 |
| `B` | `money` ×1e-9 |
| `M` | `money` ×1e-6, `shares` ×1e-6, `volume` ×1e-6 |
| `K` | `money` ×1e-3 |
| `배` | `multiple` ×1 |
| `x` | `multiple` ×1 |
| `건` | `count` ×1 |
| `주` | `shares` ×1, `volume` ×1 |
| `bp` | `fraction` ×1e4, `percent` ×100 |
| `(통화)` | `price` ×1, `money` ×1 |
| `(없음)` | `multiple` ×1, `price` ×1, `count` ×1, `other` ×1 |

- `(통화)`: 단위 없이 통화 기호(₩·$)만 있는 숫자. `(없음)`: 단위도 통화 기호도 없는 숫자.
- 표에 없는 단위(`GB`, `TB`, 숫자 뒤에 붙은 그 밖의 영문 `W`·`D` 등)는 스냅샷과 대조하지 않는다(인용이 있으면 `cited`, 없으면 `unsupported`).
- *(구현 중 조정, T010)*: 처음에는 단위별 배율을 모든 경로에 적용했으나, 검증 세트에서 "107.4조" ↔ 지수 거래량×10⁻¹², "70%" ↔ 배당수익률(퍼센트 값)×100 같은 우연한 일치가 생겨 경로 종류로 묶었다.

### 4-4. 부호

표기에 `+`·`-`가 있으면 후보와 부호가 같아야 한다(0은 둘 다 허용). 부호가 없으면 절댓값으로 비교한다.

### 4-5. 정보량 낮은 숫자

소수점 없는 두 자리 이하 정수(|값| < 100)와 0은 스냅샷 값 수천 개 중 어딘가와 우연히 맞기 쉬워 **스냅샷과 대조하지 않는다**.

- 같은 문장(표 행)이 `Section 4 › N` 또는 `Section 4 › N-M`으로 Section 4 표를 가리키고, 그 표(`### N.`·`#### N-M.` 제목 아래)에 단위·통화·값이 같은 표기가 있으면 `script`로 본다(경로 `section4 › N`). 표는 건수를 단위 없이 쓰므로(`상향 7 / 하향 25`) 본문의 `건`은 표의 단위 없는 숫자와 같은 단위로 보고, 표 안의 한 자리 숫자는 번호로 제외하지 않는다.
- 그 밖에는 인용이 있으면 `cited`, 없으면 `unsupported`.
- **유효숫자 두 자리 이하**(예: `2.4`, `0.81`, `₩380,000`): 종목 문맥(4-6)이 있으면 문맥 경로에서만 찾고, 없으면 대조하지 않는다.
- *(구현 중 조정, T010)*: 종목 문맥으로 범위를 좁혀도 "49%" ↔ 영업이익률 48.6%, "40%"(배분 비중) ↔ ROE 39.97% 같은 우연한 일치가 남았다. 검증 세트에서 작은 정수가 스냅샷과 정당하게 맞은 경우는 없었다.

### 4-6. 약한 일치

**종목 문맥**: 같은 줄에 나온 종목·지수(스냅샷 `meta.args.tickers`·`benchmarks`) 전부, 없으면 가장 가까운 상위 제목의 종목. 코드뿐 아니라 별칭으로도 찾는다.

- 보고서 별칭: 보고서 어디서든 `이름(코드)`로 쓴 이름(예: `삼성전자(005930.KS)`, `마이크론 (MU)`). 두 글자 이상이고 `지수`·`기업`·`종목`·`티커`·`코드`가 아닌 것.
- 지수 별칭: 아래 표.

| 키 | 별칭 |
|---|---|
| `^KS11` | KOSPI, 코스피 |
| `^KQ11` | KOSDAQ, 코스닥 |
| `^SOX` | SOX, 필라델피아 반도체 |
| `^GSPC` | S&P 500, S&P500 |
| `^IXIC` | NASDAQ, 나스닥 |

문맥 경로는 그 종목들의 `{티커}.`, 판정 기준값 `rules.`, 지수 `^…`(어느 문장에서든 인용 가능)이다.

종목 문맥이 있는데 문맥 경로에서는 맞지 않고 다른 종목 경로에서만 맞으면 **일치로 보지 않는다**(인용이 있으면 `cited`, 없으면 `unsupported`). 대신 `weak`로 표시하고 맞은 경로를 문제 설명에 적는다(다른 종목 값을 옮겨 썼거나 우연히 같은 값).

### 4-7. 여러 경로와 일치

문맥 종목의 경로를 우선하고, 그다음 4-3 표의 순서(앞 종류)를 우선한다. 일치한 경로 수를 함께 적는다.

### 4-8. 근사 표현

숫자 바로 뒤에 `부근`·`내외`·`안팎`·`가량`·`전후`가 붙으면(사이에 `원`이 있어도) 근사값이므로 스냅샷과 대조하지 않는다(인용이 있으면 `cited`, 없으면 `unsupported`). 예: "볼린저 중심선 ₩262,000 부근"(실제 값 ₩262,312).

## 5. 분류

순서: 제외 → 스냅샷 일치(`script`) → 인용 범위 안 인용(`cited`) → 나머지(`unsupported`).

**인용 범위**: 같은 문장(`다.`·`. `·`<br>`·줄바꿈으로 나눔, 목록 항목도 문장 단위) 또는 같은 표 행(`|`로 시작하는 줄 하나). 범위 안의 `[n]`이 그 범위 숫자 전체의 인용이다.

**직접 계산 금지**: 스냅샷 값으로 AI가 계산한 숫자(합계·차이·비율 등, 스크립트가 내지 않는 값)는 `unsupported`다. 같은 값의 단위·표기만 바꾼 것은 4-3 규칙으로 일치한다.

## 6. 참고문헌 형식

- 항목: 참고문헌 구간의 `[n] …` 줄. `[n] 제목 — 발행일 — URL`과 `[n] [제목](URL) — 발행일`을 모두 읽는다.
- 필수: 제목, 발행일(`YYYY-MM-DD`), URL.
- **홈페이지 주소**: 경로가 비었거나 `/`, `/index.html`, `/index.htm`, `/main`, `/home`뿐이고 쿼리가 없는 URL. 출처로 인정하지 않는다.
- 본문의 인용 번호가 참고문헌에 없으면 `missing_citation_target`(오류), 참고문헌이 본문에서 쓰이지 않으면 `unused_reference`(경고).

## 7. 기사 대조 (`--fetch-sources`, 로컬 전용)

| 키 | 뜻 |
|---|---|
| `found` | 그 번호로 인용된 숫자가 모두 문서에 있음 |
| `not_found` | 문서에 없는 숫자가 있음 |
| `unverifiable` | 접속 실패, 홈페이지 주소, 본문 글자 500자 미만(유료·차단 추정) — 통과 아님 |

제한 시간 10초, 재시도 없음. 문서 숫자는 3장의 규칙으로 읽고, 같은 단위끼리 4-1 허용 오차로 비교한다(`조`↔`억`은 서로 환산).

## 8. 결과와 종료 코드

| 키 | 뜻 |
|---|---|
| `0` | 기록되지 않은 오류 없음 |
| `1` | 기록되지 않은 오류 있음 |
| `2` | 실행 불가(보고서 없음·읽기 실패·인자 오류) |

- 문제 ID: 숫자 문제는 `{섹션 제목 SHA-1 앞 4자}-{원문 표기}-{같은 섹션 안 같은 표기의 순번}`, 그 밖에는 `{종류}-{대상}`(예: `reference_format-7`).
- '숫자 점검 결과' 섹션: 참고문헌 목록 뒤, 면책 문구 앞에 `## 9. 숫자 점검 결과 (스크립트 자동 점검)`으로 넣는다. 다시 점검할 때 머리 줄의 개수가 현재 결과와 같고, 남은 문제의 ID가 표에 있고 사유가 `[AI_TODO]`가 아니면 그 문제는 '기록됨'이다.
- 짝 스냅샷이 없으면 `no_snapshot`, Section 4 기준본이 없으면 `no_baseline` 오류를 낸다(조용히 통과하지 않음).
