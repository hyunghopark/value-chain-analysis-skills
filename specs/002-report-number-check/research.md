## R3. 숫자 찾기와 제외 규칙

- **Decision**: 정규식 토크나이저 하나로 `부호 + 통화 기호 + 숫자(쉼표·소수) + 단위`를 읽는다. 한글 금액("3조 9,334억 원")은 하나로 합치고, 범위("26.5%~31.2%")는 둘로 나눈다. 아래는 수량이 아니므로 제외하고 범주별로 개수만 센다.

| 범주 | 예 | 판별 |
|---|---|---|
| 날짜·시각 | 2026-10-28, 10-14, 10월 28일, 15:00 | 날짜 패턴 |
| 연도 | 2027년, 2022→2023 | 단위 없는 19xx·20xx 정수 |
| 분기·회계 표기 | 3Q26, FY4Q26, 2Q26 | 영문자와 붙은 숫자 |
| 기간 | 30일, 5거래일, 20일간, 12M | 정수 + 기간 단위(일·거래일·개월·년·M) |
| 번호 | 6.1, 7.2, 1), 목록 번호, Section 4 › 1-1 | 줄 머리·제목·섹션 참조 |
| 인용·사건 번호 | [7], KI-001 | 패턴 |
| 종목 코드 | 005930, 005930.KS | 6자리 숫자(.KS/.KQ) |
| 제품·공정·규격 | HBM4, DDR5, MI350, 16-Hi, 4나노, 3nm, 12단, 2048-bit | 영문자와 붙은 숫자, 규격 단위 |
| 다이어그램 서식 | `#512da8`, `stroke-width:2px` | Mermaid `style`·`classDef` 줄 |

  용량 단위(GB·TB 등)가 붙은 숫자는 수량으로 본다(spec Edge Cases '16GB~32GB'). 제외하는 규격 단위는 nm·나노·단·Hi·bit다.

- **Rationale**: 측정한 미일치 잡음이 모두 이 범주에 들었다. 범주 목록과 규격 단위는 규칙 원본에 두어 검증 세트(SC-003)로 조정한다.
- **Alternatives**: 형태소 분석기 — 의존성이 늘고 숫자 단위 판별에 이득이 작아 버림.

## R4. 스크립트 값 일치 판정

- **Decision**:
  1. **표시 자릿수 허용 오차**: 본문 표기의 소수 자릿수가 d이면 |후보 − 표기| ≤ 0.5×10⁻ᵈ.
  2. **단위 환산**: 단위별로 후보 배율을 시도한다. `%`·`%p` → ×100, ×1 / `조` → 원 ×10⁻¹², 억 원 ×10⁻⁴ / `억` → 원 ×10⁻⁸, 억 원 ×1 / `T`·`B`·`M` → ×10⁻¹²·10⁻⁹·10⁻⁶ / `배`·`x`·단위 없음 → ×1. 통화 기호(₩·$)는 값 비교에서 무시한다.
  3. **부호**: 표기에 +·− 부호가 있으면 후보와 부호가 같아야 한다. 부호가 없고 말로 방향을 쓴 경우("34.3% 하락")는 절댓값으로 비교한다.
  4. **정보량 낮은 숫자**: 소수점 없는 두 자리 이하 정수(예: 7건, 25건, 62%)는 우연히 일치하기 쉽다. 가장 가까운 상위 제목이나 같은 줄에 종목이 특정되면 그 종목의 경로에서만 찾는다. 종목을 특정할 수 없으면 대조하지 않는다. *(구현 중 조정, T010: 처음에는 '일치로 분류하되 `weak` 표시'였으나 검증 세트에서 23건 중 대부분이 우연한 일치였고 "6배"처럼 근거 없는 주장이 통과했다. `weak`는 '종목 문맥이 있는데 다른 종목 경로에서만 맞음'으로 뜻을 바꿨다.)*
  5. 같은 숫자가 여러 경로와 일치하면 문맥 종목의 경로를 우선하고, 나머지 개수도 함께 적는다.
- **Rationale**: 측정에서 2번까지만으로 본문 131/185, Section 4 499/694가 일치했다. 남은 미일치는 대부분 잡음과 스냅샷 누락이라 대조 규칙의 문제가 아니었다. 4번은 SC-001의 "잘못 통과 0건"을 지키기 위한 장치다.
- **Alternatives**: 고정 상대 오차(0.05%) — 소수 한 자리 반올림 값(RSI 38.3 ↔ 38.27)을 놓쳐 버림. 문장 의미 해석으로 지표 이름까지 맞추기 — 효과 대비 복잡해 이후 단계로 미룸.

## R5. 인용 인정 범위

- **Decision**: 문단을 문장으로 나눈다(`다.`·`. `·`<br>`·줄바꿈 기준). 같은 문장 안의 `[n]`(`[n], [m]` 포함)을 그 문장 숫자 전체의 인용으로 본다. 표는 `|`로 시작하는 줄 하나가 범위다. 목록 항목(`- `)도 문장 단위로 나눈다(항목 전체를 한 범위로 보지 않음 — spec FR-005).
- **Rationale**: 측정 보고서의 인용 위치(문장 끝, 표의 '출처' 칸)를 모두 덮는다.
- **Alternatives**: 문단 단위 — 인용 없는 숫자가 같은 문단의 다른 인용에 묻혀 버림.

## R6. 참고문헌 형식

- **Decision**: '참고 문헌'·'References' 제목 아래의 `[n] ...` 줄을 항목으로 읽는다. 필수: 제목, `YYYY-MM-DD` 발행일, URL. URL은 경로가 비었거나 `/`·`/index.html` 등 첫 화면이면 '홈페이지 주소'로 판정한다. 본문 인용 번호와 참고문헌 번호를 서로 대조해 '없는 인용'과 '미사용 참고문헌'을 낸다.
- **Rationale**: 측정 보고서의 17건은 모두 `https://www.도메인` 형태였다. 템플릿이 요구하는 형식(`[번호] 제목 — 발행일 — URL`)과 실제 쓰인 형식(`[n] [제목](URL) — 날짜`)을 둘 다 읽는다.

## R7. 기사 대조 (선택 실행)

- **Decision**: `--fetch-sources` 옵션을 줄 때만 실행한다. 형식 점검을 통과한 참고문헌마다 `requests`로 내려받아(제한 시간 10초, 재시도 없음) `beautifulsoup4`로 본문 글자를 뽑고, R3·R4와 같은 숫자 해석으로 그 번호를 인용한 숫자가 문서에 있는지 확인한다. 결과는 `found`·`not_found`·`unverifiable`(접속 실패, 홈페이지 주소, 본문 글자 500자 미만 — 유료·차단 추정). `unverifiable`은 통과로 치지 않는다.
- **Rationale**: 기존 의존성만 쓴다. 국내 사이트 접속이 불안정하므로 CI에서는 실행하지 않는다(헌법 기술 제약). 테스트는 응답을 흉내 내서(mock) 한다.
- **Alternatives**: 내려받은 문서를 캐시·저장 — 저작권·용량 문제와 Clean-Slate를 고려해 이번에는 하지 않음.

## R9. '숫자 점검 결과' 섹션과 남은 예외

- **Decision**: 점검 도구는 보고서에 붙일 '## 9. 숫자 점검 결과' 블록을 출력한다(분류별 개수, 점검 시각, 남은 문제마다 고유 ID와 `사유: [AI_TODO]`). AI가 이 블록을 참고문헌 목록 뒤(면책 문구 앞)에 넣고 사유를 채운다. 다시 점검할 때 이 섹션은 대조 대상에서 빼고, (1) 섹션이 있는지, (2) 섹션의 개수가 현재 점검과 같은지, (3) 남은 문제의 ID가 모두 사유와 함께 적혀 있는지 확인한다. 셋 다 맞으면 남은 문제는 '기록된 예외'로 보고 종료 코드 0을 낸다.
- **문제 ID**: `{섹션 제목 해시 4자}-{원문 표기}-{같은 섹션 안 몇 번째 등장}`. 줄 번호는 편집하면 바뀌므로 쓰지 않는다.
- **Rationale**: 점검 도구는 보고서를 고치지 않는다(FR-014). "남은 항목을 적지 않고 마무리하지 않는다"(FR-011)를 스크립트가 확인할 수 있다.
- **Alternatives**: 점검 도구가 섹션을 직접 써넣기 — FR-014 위반이라 버림.

## R10. Section 4와 스냅샷 대응 (FR-015)

- **Alternatives**: 판정 기준값을 점검 도구가 규칙 문서에서 직접 읽기 — 규칙 문서는 사람이 읽는 글이라 파싱이 깨지기 쉬워 버림. 코드 상수를 스냅샷에 남기면 "숫자는 스크립트 산출값"(헌법 II)으로 설명된다.

## R11. 검증 세트 (SC-001·SC-003)

- **Decision**: 측정 보고서와 그 스냅샷을 `tests/fixtures/002/`에 복사한다. 본문 숫자마다 기대 분류(`script`·`cited`·`unsupported`·`excluded`)를 적은 `labels.json`을 만든다. 초안은 점검 도구 결과로 만들고, **사람이 전부 검토해 확정**한다(도구 결과를 그대로 정답으로 쓰지 않는다). 테스트는 일치율 95% 이상과 `unsupported`인데 다른 분류로 나온 것 0건을 확인한다.
- **Rationale**: SC-001의 정답은 사람이 정해야 한다. 고정 자료라 네트워크 없이 CI에서 돈다.
- **위험**: 측정 스냅샷은 001 보완 이전 버전이라 '5일 누적'·지분율이 없다. 그 숫자들은 이 자료 기준으로 `unsupported`가 정답이다. 보완 후 동작은 별도 합성 자료로 시험한다.

## R12. 성능

- **Decision**: 단순 반복(본문 약 200개 × 스냅샷 값 약 3,000개 × 배율 4개 ≈ 240만 번 비교, Section 4 약 700개 ≈ 840만 번)으로 충분하다. 10초를 넘으면 값을 반올림 키로 묶는 색인을 추가한다.
- **Rationale**: SC-006(네트워크 없이 10초 이내). 시제품은 본문과 Section 4를 모두 대조하는 데 0.55초가 걸렸다.
