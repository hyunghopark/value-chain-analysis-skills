# Feature Specification: 수집·정제·계산·출력 분리

**Feature Branch**: `claude/003-pipeline-split` (스펙 폴더는 `.specify/feature.json`으로 지정)

**Created**: 2026-10-19

**Status**: Draft

**Input**: 로드맵 3단계 — "계산·표 생성이 스냅샷만 읽는다. 같은 스냅샷이면 같은 보고서가 나온다" ([ROADMAP](../../ROADMAP.md)). 1단계([001](../001-data-snapshot/spec.md))의 스냅샷과 2단계([002](../002-report-number-check/spec.md))의 Section 4 기준본 위에 쌓는다.

## 배경

001은 수집한 값을 출처·기준·시점과 함께 스냅샷에 남겼고, 002는 보고서 숫자가 그 스냅샷과 맞는지 점검한다. 하지만 스냅샷은 아직 '결과 기록'일 뿐, Section 4를 만드는 입력이 아니다. 지금은 데이터 수집, 보완·교정, 지표·판정 계산, 표 출력이 한 번의 실행 안에서 섞여 있다.

현재 코드 조사 결과(2026-10-19, `get_financial_stats.py`):

| 관찰 | 내용 |
|---|---|
| 표를 만드는 도중 외부 접속 | 수급 표(네이버·다음 3개 경로), 시장 비교 표(지수 1년 시세)는 표 생성 함수 안에서 데이터를 받는다 |
| 계산·출력이 현재 시각을 읽는 곳 | 5곳: NTM EPS 기간 가중, 실적 발표일 계산, 수급 표의 장 마감(15:40) 판단, 데이터 기준 블록의 시각, 날짜 역산 |
| 스냅샷에 없는 계산 입력 | 연간·분기 손익계산서, 분기 재무상태표(사이클·P/B 밴드·일회성 손익 감사), 컨센서스 표 전체(추정치·추이·수정·서프라이즈 이력), 5년 가격 이력의 OHLC, 네이버 원자료 |
| 스냅샷에 있는 것 | 표에 표시된 값과 일부 원값(종목당 수십~백여 개 경로), 종가·거래량 시계열, 경고 문장 |
| 002 판정 불변 확인(T037)의 제약 | 같은 입력을 다시 만들 수 없어 `main`과 브랜치를 22초 간격으로 실행해 비교했고, 그 사이 시세가 움직여 2행이 달랐다 |

그래서 (1) 보고서를 나중에 같은 데이터로 다시 만들어 확인할 수 없고, (2) 판정 규칙을 바꿀 때 전후 비교(헌법 V)가 실시간 데이터 변동에 흔들리며, (3) 표를 만드는 코드가 몰래 외부 데이터를 다시 읽어 스냅샷과 다른 값을 낼 여지가 있다(헌법 II·III).

## Clarifications

### Session 2026-10-19

- Q: 저장한 스냅샷으로 옵션만 바꿔 다시 계산하는 범위는? → A: 시나리오 확률과 순환업종 지정(추가·제외)만 허용한다. 결과는 별도 파일로 남기고, 스냅샷에 없는 데이터가 필요한 옵션(종목·지수 추가)은 거부한다. 부족분만 추가 수집하는 방식은 한 보고서에 수집 시점이 섞여 출처 추적(헌법 II)을 복잡하게 하므로 하지 않는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 스냅샷만으로 Section 4 다시 만들기 (Priority: P1)

보고서 검토자가 보고서의 짝 스냅샷 하나를 넣으면, 인터넷 연결 없이 언제 실행해도 보고서 생성 때와 글자 하나까지 같은 Section 4를 받는다. 저장된 Section 4 기준본과 다르면 어느 줄이 왜 다른지 보고받는다.

**Why this priority**: 로드맵 3단계의 완료 기준 그 자체다. 이것이 되면 스냅샷이 보고서의 완전한 근거가 되고, 나머지 이야기(규칙 변경 비교, 옵션 재계산)가 모두 이 위에서 동작한다.

**Independent Test**: 4개 종목(한국 2, 미국 2) 보고서를 만들고, 네트워크를 막은 상태에서 다른 날짜·시각으로 설정해 스냅샷에서 Section 4를 다시 만든다. 보고서 안의 Section 4와 비교한다.

**Acceptance Scenarios**:

1. **Given** 새 형식으로 만든 보고서와 짝 스냅샷, **When** 네트워크를 막고 다음 날 다시 만들면, **Then** Section 4가 보고서 생성 때와 같다(데이터 기준 시각, 수급 표의 장중·마감 구분, 품질 경고 문장 포함).
2. **Given** 수집 시점이 장중(한국 15:40 이전)인 스냅샷, **When** 장 마감 후에 다시 만들면, **Then** 수급 표는 수집 시점 기준(장중 추정 표시)으로 나온다.
3. **Given** 스냅샷의 계산 결과 값 하나를 손으로 바꿈, **When** 다시 만들면, **Then** 다시 계산한 값과 저장된 값이 다르다는 사실을 경로·저장값·재계산값과 함께 보고하고, 어느 값도 조용히 덮어쓰지 않는다.
4. **Given** 계산에 필요한 원자료(예: 분기 재무상태표)가 빠진 스냅샷, **When** 다시 만들면, **Then** 빠진 경로를 밝히는 오류로 멈추고 임의 기본값으로 표를 만들지 않는다.
5. **Given** 수집 때 출처 하나가 실패해 경고와 함께 일부 표가 비었던 보고서, **When** 스냅샷에서 다시 만들면, **Then** 같은 경고와 같은 빈 표가 나온다(실패도 기록된 입력이다).
6. **Given** 001·002 시기 형식의 스냅샷, **When** 다시 만들기를 시도하면, **Then** '원자료가 없는 이전 형식이라 다시 만들 수 없음'을 알리고 끝난다. 002 숫자 점검은 이전 형식에서도 그대로 동작한다.

---

### User Story 2 - 같은 입력으로 규칙 변경 전후 비교 (Priority: P2)

스킬 개발자가 판정 기준값이나 계산 방식을 바꿀 때, 저장해 둔 스냅샷으로 바꾸기 전 코드와 바꾼 뒤 코드의 Section 4를 만들어 비교한다. 다른 줄은 모두 코드 변경 때문이므로, 판정이 바뀐 이유를 PR에 정확히 적을 수 있다(헌법 V).

**Why this priority**: 지금은 실시간 데이터라 전후 비교가 시세 변동에 섞인다(T037의 2행). 판정 로직을 고치는 모든 이후 작업(4단계 공식 출처 전환, 보류 중인 사이클 판정 개선)의 검증 방법이 된다.

**Independent Test**: 기준값 하나(예: Forward P/E 기준)를 바꾼 코드와 원래 코드로 같은 스냅샷에서 Section 4를 만들고, 차이가 그 기준값을 쓰는 칸과 그에 따른 판정·종합 판단에만 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 같은 스냅샷과 같은 코드, **When** 두 번 만들면, **Then** 결과가 같다(차이 0줄).
2. **Given** 같은 스냅샷과 기준값 하나를 바꾼 코드, **When** 비교하면, **Then** 차이는 그 기준값이 영향을 주는 신호·판정·종합 판단과 '판정 기준값' 기록에만 나타난다.
3. **Given** 출력 형식만 바꾼 코드(예: 표 문구), **When** 비교하면, **Then** 계산 결과 값은 모두 같고 글자만 다르다는 것을 구분해 보고한다.

---

### User Story 3 - 수집 없이 분석 옵션만 바꿔 다시 계산 (Priority: P3)

분석가가 이미 만든 보고서의 스냅샷으로, 데이터를 다시 받지 않고 시나리오 확률이나 순환업종 지정만 바꿔 Section 4를 다시 계산해 본다. 원래 보고서와 스냅샷은 그대로 남는다.

**Why this priority**: 같은 데이터에서 가정만 바꿔 보는 것은 판단 검증 도구(헌법 I)로서 유용하지만, US1·US2 없이는 성립하지 않는 부가 기능이다.

**Independent Test**: 시나리오 확률을 바꿔 다시 계산하고, 바뀐 것이 시나리오 표와 기대 수익률뿐이며 원래 파일이 바뀌지 않았는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 기존 스냅샷, **When** 시나리오 확률을 바꿔 다시 계산하면, **Then** 시나리오 표와 기대값만 달라지고, 결과에는 '원본 스냅샷 + 바꾼 옵션'이 기록된다.
2. **Given** 기존 스냅샷, **When** 수집하지 않은 종목·지수를 추가하려 하면, **Then** 스냅샷에 없는 데이터라 계산할 수 없다고 알린다(새로 수집하지 않는다).
3. **Given** 다시 계산한 결과, **When** 저장하면, **Then** 원래 보고서·스냅샷을 덮어쓰지 않고 별도 파일로 남는다.

---

### Edge Cases

- **장중 수집**: 잠정 값과 '장중 추정' 표시는 수집 시각으로 결정된다. 다시 만드는 시각과 무관하다.
- **실적 발표일·NTM 가중**: 오늘 날짜가 들어가는 계산은 모두 수집 시각을 '오늘'로 쓴다.
- **환경 차이**: 라이브러리 버전이 달라 계산이 미세하게 달라질 수 있다. 스냅샷에 기록된 버전과 다르면 경고하고, 결과가 다르면 US1 시나리오 3처럼 보고한다.
- **부동소수점 표기**: 원자료를 저장했다 읽을 때 값이 바뀌어 반올림 결과가 달라지면 안 된다.
- **교정·보완 값**: 정제 단계의 교정(원래 값과 KI 번호 포함)은 스냅샷에 남고, 계산은 교정된 값을 읽는다. 다시 만들 때 교정을 다시 하지 않는다.
- **원자료가 큰 경우**: 5년 일별 시세처럼 큰 자료로 스냅샷이 커진다. 계산에 쓰는 범위만 저장하되, 쓰는 것은 빠짐없이 저장한다.
- **수집 실패**: 출처 실패도 '없음'으로 기록한다. 기록이 없는 것(형식 오류)과 수집했으나 비어 있는 것을 구분한다.
- **Section 4 기준본이 사람 손으로 바뀐 보고서**: 다시 만든 결과와 기준본·보고서 본문 세 가지를 구분해 비교한다(002의 Section 4 변경 감지와 겹치지 않게, 이쪽은 '스냅샷 → Section 4' 재현만 확인한다).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 보고서 데이터 처리를 네 단계로 나눈다. **수집**(외부 출처 접속), **정제**(출처 간 대조, 보완·교정, 데이터 품질 경고), **계산**(지표·신호·판정·시나리오), **출력**(표와 문구). 외부 출처 접속은 수집 단계에서만 한다.
- **FR-002**: 수집·정제가 끝나면 계산에 필요한 입력을 모두 스냅샷에 기록한다. 원자료(재무제표, 컨센서스 표, 가격 이력, 지수 시세, 수급 원자료), 수집 시각, 실행 옵션, 출처 실패 기록을 포함하고, 각 값의 출처·기준·시점·상태는 001 규칙을 따른다.
- **FR-003**: 계산·출력 단계는 스냅샷과 규칙·코드만 읽는다. 외부 접속을 하지 않고, 현재 시각 대신 스냅샷의 수집 시각을 쓴다.
- **FR-004**: 같은 스냅샷, 같은 코드, 같은 옵션이면 Section 4가 글자 단위로 같아야 한다. 데이터 기준 블록, 수급 표의 장중·마감 구분, 데이터 품질 경고, 판정 기준값 기록을 포함한다.
- **FR-005**: 스냅샷 하나를 받아 Section 4를 다시 만드는 실행 방법을 제공한다. 스냅샷에 저장된 Section 4 기준본이 있으면 비교해 다른 줄을 보고하고, 차이 여부를 종료 코드로 구분한다.
- **FR-006**: 다시 계산한 값이 스냅샷에 저장된 계산 결과와 다르면 경로, 저장값, 재계산값을 보고한다. 어느 쪽도 조용히 덮어쓰지 않는다(헌법 III).
- **FR-007**: 계산에 필요한 입력이 스냅샷에 없거나 형식이 맞지 않으면, 빠진 경로를 밝히는 오류로 멈춘다. 수집 때 실패해 '없음'으로 기록된 입력은 오류가 아니며, 생성 때와 같은 경고와 표를 낸다.
- **FR-008**: 001·002 형식(원자료가 없는) 스냅샷은 다시 만들기 대상이 아님을 알리고 끝낸다. 002 숫자 점검 도구는 이전 형식과 새 형식을 모두 읽는다.
- **FR-009**: 사용자가 쓰는 보고서 생성 명령, 출력 파일(보고서, `_data.json`), Section 4 형식은 바뀌지 않는다. 한 번의 실행 안에서도 Section 4는 방금 저장한 스냅샷에서 만든다(생성과 재현이 같은 길을 쓴다).
- **FR-010**: 다시 만들기·다시 계산은 지정한 스냅샷 하나만 읽고, 다른 보고서·스냅샷은 읽지 않는다(헌법 VI).
- **FR-011**: 분석 옵션 중 시나리오 확률과 순환업종 지정(추가·제외)은 스냅샷을 바꾸지 않고 다시 계산할 수 있다. 결과는 별도 파일로 남기고, 원본 스냅샷 경로와 바꾼 옵션을 기록한다. 스냅샷에 없는 종목·지수가 필요한 옵션(종목·지수 추가 등)은 거부하고, 부족분을 추가 수집하지 않는다.
- **FR-012**: 스냅샷의 원자료 형식(무엇을 어떤 경로로 저장하는지, 수집 실패 표기, 형식 버전)은 규칙 원본(`skills/financial-analyst/references/rules/data-snapshot.md`)에 둔다(헌법 IV).
- **FR-013**: 스냅샷에는 형식 버전과 수집에 쓴 라이브러리 버전을 기록한다. 다시 만들 때 버전이 다르면 경고한다.
- **FR-014**: 이 분리는 판정·계산 결과를 바꾸지 않는다. 분리 전 코드와 같은 시각 실행으로 비교해 판정·종합 판단이 같아야 하고, 다르면 원인을 PR에 적는다(헌법 V).

### Key Entities

- **원자료 (Raw input)**: 수집 단계가 출처에서 받은 자료. 재무제표·컨센서스 표·가격 이력·수급 행처럼 표 형태일 수 있다. 출처·기준·시점·상태와 수집 성공·실패 여부를 가진다.
- **정제 기록 (Refinement record)**: 출처 간 대조 결과, 보완·교정(원래 값과 KI 번호), 데이터 품질 경고.
- **계산 결과 (Derived value)**: 지표·신호·판정·시나리오 값. 001·002가 대조에 쓰는 값이며, 다시 계산해 저장값과 비교할 수 있다.
- **실행 정보 (Run context)**: 수집 시각(계산의 '오늘'), 실행 옵션, 형식 버전, 라이브러리 버전, 코드 버전.
- **재현 결과 (Reproduction result)**: 다시 만든 Section 4, 기준본과의 차이, 계산 결과 불일치 목록, 버전 경고.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 4개 종목(한국 2, 미국 2)으로 만든 새 형식 스냅샷에서, 네트워크를 막고 다른 날짜·시각(장중·장 마감 후 각각)으로 Section 4를 다시 만들면 보고서 안의 Section 4와 다른 줄이 0줄이다.
- **SC-002**: 계산·출력 단계 실행 중 외부 접속 시도와 현재 시각 읽기가 0회다(테스트에서 둘 다 막고 실행해 통과).
- **SC-003**: 스냅샷의 계산 결과 값을 바꾼 경우와 원자료를 뺀 경우를 테스트에서 100% 감지하고, 보고에 경로가 들어 있다.
- **SC-004**: 분리 전 코드와 분리 후 코드를 같은 시각에 실행해 비교하면, 판정 기호가 있는 행과 종목별 종합 판단이 100% 같다.
- **SC-005**: 같은 스냅샷에서 기준값 하나만 바꿔 비교한 테스트에서, 차이가 그 기준값의 영향 범위 밖에 나타나는 경우가 0건이다.
- **SC-006**: 4개 종목 스냅샷에서 Section 4 다시 만들기가 네트워크 없이 10초 안에 끝나고, CI에서 실행된다(저장소에 커밋한 시험용 스냅샷 사용).
- **SC-007**: 새 형식 스냅샷 크기가 4개 종목 보고서 한 건당 10MB 이하다.
- **SC-008**: 002 검증 세트 결과(분류 일치율 95% 이상, 잘못 통과 0건)와 기존·신규 테스트, CI가 모두 그대로 통과한다.

## Assumptions

- '같은 보고서'는 스크립트가 만드는 Section 4(정량 데이터 분석 결과)를 뜻한다. AI가 채우는 본문과 가치사슬 다이어그램은 데이터 계산이 아니므로 범위 밖이다.
- 비교는 글자 단위다. 숫자 반올림·공백·줄 순서가 달라도 '다르다'로 본다.
- 다시 만들기는 같은 코드를 전제로 한다. 코드가 다르면 결과가 다를 수 있고, 그 차이를 보는 것이 US2의 목적이다.
- 수집 시각을 '오늘'로 쓰는 것은 보고서 내용의 의미를 바꾸지 않는다(보고서는 수집 시점의 판단이다).
- 이전 형식 스냅샷을 새 형식으로 바꾸는 변환은 하지 않는다. 원자료가 없어 변환할 수 없다.
- 시험용 스냅샷(실제 종목 데이터)은 002 검증 세트와 같이 테스트 자료로만 쓰고, 기업별 결론은 위키에 넣지 않는다(헌법 VI).
- 스냅샷이 커지는 것은 받아들인다. 저장 범위는 '계산이 읽는 것 전부, 읽지 않는 것은 저장하지 않음'을 기준으로 plan에서 정한다.
- 범위 제외: 공식 출처 전환(004), 사이클 판정 개선(보류), AI 본문 생성 방식, 002 점검 규칙 변경.
