# 001. 데이터 스냅샷과 출처 정보 — 요구사항

- 상태: 확정 (2026-10-14)
- 작성: 2026-10-14
- 관련: [로드맵 1단계](../../ROADMAP.md), [데이터 품질 규칙](../../skills/financial-analyst/references/rules/data-quality.md), KI-001~008

## 배경

보고서를 검증하려면 숫자마다 "어디서, 어떤 기준으로, 언제" 왔는지 다시 추적해야 한다. 2026-10-14 세션에서 겪은 문제 대부분이 여기서 나왔다.

| 겪은 문제 | 원인 |
|---|---|
| '종가'가 출처마다 다름 (정규장 vs 수급 데이터) | 숫자에 가격 기준이 붙어 있지 않음 (KI-001) |
| 수급 금액을 정규장 종가로 잘못 '고침' | 수량과 가격이 같은 데이터에서 왔다는 정보가 없음 |
| 마이크론 사이클 판정이 갱신 시점에 따라 바뀔 수 있음 | 재무제표의 기준 기간이 표시되지 않음 (KI-003) |
| 기사 수치(하이닉스 10/12 -3.4%) 오인용 | 기사 수치를 수집 데이터와 대조할 수단이 없음 |
| 코스피 10/13 결측이 실행 시점마다 다름 | 실행 당시 데이터가 남지 않아 재현·검증 불가 (KI-002) |

## 목표

1. 보고서를 만들 때 수집한 데이터를 **스냅샷 파일**로 남긴다.
2. 스냅샷의 각 값에 **출처 정보**(출처, 기준, 시점, 상태)를 붙인다.

## 요구사항

| ID | 요구사항 |
|---|---|
| R1 | 보고서마다 같은 이름의 스냅샷 `<보고서 파일명>_data.json`을 보고서 옆에 저장한다. 기존 파일을 덮어쓰지 않는다(보고서 버전 규칙 `_v2`를 따른다). |
| R2 | 각 값은 `value`, `source`, `basis`, `as_of`, `status`를 가진다. 필요하면 `note`, `ki`(사건 번호), `original`(교정 전 값)을 가진다. |
| R3 | `basis`는 정해진 어휘만 쓴다. 최소한 `krx_regular_close`(거래소 정규장 종가), `flow_feed_price`(수급 데이터 가격), `yahoo_close`, `quote`(현재가), `statement`(재무제표 기간 값), `consensus`(컨센서스 추정), `derived`(스크립트 계산값)를 구분한다. |
| R4 | `status`는 `final`(확정), `provisional`(장중·잠정), `estimated`(추정), `corrected`(교정)로 나눈다. 교정·보완한 값은 `original`과 `ki`를 함께 기록한다. 예: Yahoo 빈 종가 → 거래소 종가, KI-002. |
| R5 | 보고서 Section 4의 표에 나오는 값은 모두 스냅샷에서 찾을 수 있어야 한다. 계산값은 입력값의 경로(`inputs`)를 기록한다. |
| R6 | 데이터 품질 경고(`[KI-xxx]` 포함)를 스냅샷에도 목록으로 남긴다. |
| R7 | 스냅샷 머리에 생성 시각(KST), 실행 인자, 라이브러리 버전(yfinance 등), 스킬 저장소 커밋(가능하면)을 기록한다. |
| R8 | 스냅샷 저장에 실패해도 보고서는 만든다. 대신 보고서 상단과 데이터 품질 경고에 실패를 표시한다. |
| R9 | 파일 크기를 제한한다. 가격 이력은 종목당 최근 260거래일의 종가·거래량만 담는다. |
| R10 | investment-strategy의 Clean-Slate 원칙을 스냅샷에도 적용한다. 새 분석은 과거 스냅샷을 읽지 않는다(검증 목적의 비교만 허용, 그때는 사용자가 지정). |

## 범위에서 제외

- 보고서 본문 숫자 자동 대조 → 002
- 수집·계산 구조 분리(계산이 스냅샷만 읽게 하기) → 003
- 공식 출처(DART·SEC·KRX) 전환 → 004

## 완료 기준

- [ ] 전체 보고서 생성 시 `_data.json`이 함께 생기고, 보고서 상단에 스냅샷 파일명이 표시된다.
- [ ] Section 4의 표 값(가격, 52주 범위, 수급, 기술적 지표 입력, 시장 비교, 핵심 지표, 사이클·밴드 입력, 컨센서스, 시나리오 입력)을 스냅샷에서 찾을 수 있다. 테스트로 확인한다.
- [ ] 한국 종목 종가에는 `krx_regular_close`와 `flow_feed_price`가 구분되어 있고, 보완·교정 값에 `original`·`ki`가 있다.
- [ ] 스냅샷 형식이 규칙 문서(`references/rules/data-snapshot.md`)에 정의되어 있다.
- [ ] 기존 테스트와 새 테스트가 모두 통과하고, 판정 결과가 이전과 같다.

## 결정 (2026-10-14, 열린 질문 정리)

1. 형식: **JSON 파일 하나**. 가격 이력은 260일·종가·거래량만 담아 용량을 제한한다.
2. 저장소 커밋 정보는 얻을 수 있으면 기록하고, 없으면 비워 둔다.
3. 스냅샷을 Git에 넣을지는 **분석 프로젝트(보고서 폴더)의 선택**으로 둔다. 스킬 저장소는 관여하지 않는다.
