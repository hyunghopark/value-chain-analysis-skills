# 0001. 규칙·사실·결정을 나눠 관리한다

- 상태: 채택
- 날짜: 2026-10-14

## 배경

데이터 출처 문제(네이버 종가 기준 변경, Yahoo 한국 종목 결함 등)가 오류 없이 틀린 값을 내는 방식으로 반복됐고, 판정 기준은 SKILL.md·스크립트 범례·보고서 문구에 흩어져 있었다.

## 결정

| 종류 | 위치 | 관리 방식 |
|---|---|---|
| 판정·데이터 규칙 (우리가 정한 기준) | `skills/financial-analyst/references/rules/` | 원본은 한 곳. 코드 주석이 이 문서를 가리킨다. 스킬과 함께 배포된다. |
| 출처 사실·사건 (외부에서 관찰한 사실) | `wiki/` + `raw/` | karpathy-llm-wiki 패턴. 위키의 숫자는 `raw/` 근거와 자동 대조한다. 경고의 `[KI-xxx]`가 사건 문서 번호다. |
| 결정 이유 | `docs/decisions/` | 번호 붙인 결정 기록. 규칙을 바꿀 때 함께 쓴다. |

## 제외

- 기업별 분석 결론·판정은 위키에 넣지 않는다. investment-strategy의 Clean-Slate 원칙(과거 보고서 비참조)과 충돌하기 때문이다.
- OpenWiki 같은 코드 문서 자동 생성은 저장소 규모에 비해 비용이 커서 쓰지 않는다.

## 결과

- 장점: 경고 → 사건 문서 → 규칙으로 바로 이어진다. 위키 숫자가 근거와 어긋나면 `check_evidence.py`가 잡는다.
- 단점: 사건마다 근거 저장·ingest 습관이 필요하다.
